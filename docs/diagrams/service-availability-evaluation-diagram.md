# Діаграма алгоритмічної послідовності оцінювання доступності сервісу

Компактна Mermaid-діаграма для Рисунка 3.2 у пояснювальній записці. Деталі кожного етапу пояснюються в §3.4, тому на рисунку залишено лише основну послідовність обчислень.

```mermaid
flowchart LR
    A["Вхідні дані сценарію<br/>сервіси · пристрої · резервне живлення · H"]
    B["1. Оцінювання автономності<br/>(Availability Estimator)<br/>навантаження → час роботи → карта доступності"]
    C["2. Симуляція залежностей<br/>(Simulation Engine v1)<br/>перевірка графа → T = min(залежностей)"]
    D["Пояснюваний результат<br/>тривалість · статус · обмежувальна причина"]

    A --> B --> C --> D
```

На етапі оцінювання автономності формується карта часової доступності компонентів сценарію (`Scenario.availability`). Модуль симуляції використовує цю карту для поширення часових обмежень через граф обов'язкових функціональних залежностей і формування статусу та причинного пояснення.

Канонічні правила розрахунку: `docs/specs/user-facing-mvp-v1.md`, `docs/SIMULATION.md`, `apps/web/src/user-mvp/` і `apps/web/src/simulation/`.
